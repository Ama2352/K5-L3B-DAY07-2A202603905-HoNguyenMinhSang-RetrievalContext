# Results and privacy

Keep only artifacts needed to reproduce or audit the lab: retrieval rankings and metrics; agent traces with tool calls, context, answers, citations, timing and errors; manual reviews; and the configuration selected before test. A JSON array may contain many per-question records, so one file per question is not necessary. `results/checkpoint3/agent-dev.json` and `results/checkpoint4/agent-test.json` contain the original individual traces consolidated without changing their contents. `results/checkpoint2/exploratory.json` retains the initial failure examples, with their original filenames. The NASA corpus inventory belongs under `data/advanced/`; source PDFs and large generated assets are not tracked.

The Day 6 connection value is loaded privately from the process environment or its existing local `.env`; do not paste or commit the value. New agent and evaluation outputs redact database connection strings, known credential environment values and common token formats. Redaction is defense in depth, not a guarantee of detecting every secret; inspect any new corpus, prompt, output and staged diff before sharing. Configuration files containing secrets remain ignored. Errors are recorded after redaction rather than replaced with fabricated results.

Existing test results are historical. New retrieval methods are being developed on dev; because the old test has already been inspected, a separate new held-out test is required for independent evaluation after the updated configuration is frozen. Do not put secret values, `.env` files, redundant per-question copies, generated PDF images, model binaries or caches into `results/`.
